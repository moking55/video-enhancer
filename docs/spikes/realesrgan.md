Prove (or disprove) that the Colab worker can run Real-ESRGAN as a streaming pipeline

## Method notes

- Scale 4: `RealESRGAN_x4plus` on a 360p downscale (640x360 -> 2560x1440).
- Scale 2: `RealESRGAN_x4plus` with `outscale=2` on the 720p clip (1280x720 -> 2560x1440). This matches the
  `realesrgan-x2` preset (4x model then downscale), not a native 2x model.
- fp16 (`half=True`), tile configurable (`TILE_X4`, `TILE_X2`, default 256).
- Encode: H.264 yuv420p CRF 18 (`libx264 -preset medium`; NVENC uses `-cq 18 -preset p5`), then mux with
  `-map 1:a? -c:a copy`, no `-shortest`. FPS is the exact rational from ffprobe (e.g. `30000/1001`).
- `RealESRGANer` swallows `RuntimeError` (including CUDA OOM) inside tiled processing and leaves a black tile;
  the notebook wraps the model forward to detect this and fails the frame loudly. T16 should keep that guard.
- VRAM probe: 2 frames per tile setting after a warm-up frame; OOM is caught and recorded.
- Encoder benchmark: 150 non-AI 2560x1440 frames piped into each encoder (pure encode throughput).

## Install recipe (what the notebook does)

1. `git fetch` the pinned commit into `/content/spike/Real-ESRGAN`, write `realesrgan/version.py`
   (normally generated by `setup.py`), add the directory to `sys.path`. The repo is not `pip install`ed.
2. `pip install addict future lmdb pyyaml scikit-image scipy tqdm yapf requests` (only what is missing).
3. `pip install --no-deps basicsr==1.4.2`; on build failure, download the sdist from PyPI (hash-checked), patch
   `setup.py` `get_version()` to a constant (`locals()['__version__']` breaks on Python 3.13), install `--no-deps`.
4. Rewrite `torchvision.transforms.functional_tensor` -> `torchvision.transforms.functional` in every `.py` under the
   installed `basicsr` (affects `basicsr/data/degradations.py`), print each changed line.
5. Import-check in a fresh interpreter. Colab's torch / torchvision / numpy are never modified.
